# 0014. 방문 분석은 Umami를 직접 운영한다

- 상태: 채택
- 날짜: 2026-11-20

## 배경
홈페이지가 손님을 데려오는지 확인하려면 방문 수와 유입 경로를 알아야 한다 (ADR 0012).

## 검토한 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| Google Analytics 4 | 무료, 기능 많음 | 쿠키 사용, 데이터가 외부에 있음, 사장님에게 너무 복잡함 |
| Umami 직접 운영 | 쿠키 없음, 화면이 단순함, 데이터를 직접 소유 | 운영 부담 (컨테이너 하나 추가) |
| 측정 안 함 | 간단함 | 효과를 증명할 수 없음 |

## 결정
- 방문 분석: **Umami**를 EC2의 Docker Compose에 추가한다. DB는 기존 PostgreSQL에 별도 데이터베이스(`umami`)로 둔다.
- 검색어 분석: 구글 서치 콘솔, 네이버 서치어드바이저에 사이트를 등록한다.
- 비즈니스 지표(문의 수, 유입 경로별 문의, QR 스캔 수): Grafana에서 PostgreSQL을 데이터 소스로 대시보드를 만든다.

## 공개 범위
- 외부에 여는 Umami 경로는 추적 스크립트와 수집 엔드포인트뿐이다 (`/umami/script.js`, `/umami/api/send`).
- Umami 관리 화면은 SSM 포트 포워딩으로만 접속한다.

## 영향
- 메모리 사용이 약 200MB 늘어난다. t4g.small(2GB)에서 전체 사용량을 모니터링하고, 부족하면 t4g.medium으로 올린다.
