# 0015. 가이드·사례·갤러리는 빌드 시 HTML로 만들고, 공개하면 자동 재빌드

- 상태: 채택
- 날짜: 2026-11-20
- 대체: ADR 0004 (브라우저에서 API로 조회)

## 배경
ADR 0004는 사장님이 올린 내용이 바로 보이도록 목록을 브라우저에서 API로 불러오기로 했다.
그런데 ADR 0012로 목표가 "검색으로 새 손님 유입"이 되면서 식물 가이드와 진행 사례가 핵심 검색 콘텐츠가 됐다.
브라우저에서 불러온 내용은 HTML에 없어서 검색엔진(특히 네이버)이 잘 읽지 못한다.

## 결정
| 내용 | 방식 |
|---|---|
| 식물 가이드, 진행 사례, 작품 갤러리, 클래스 소개 | **빌드할 때 API에서 받아 HTML로 생성** (Next.js `generateStaticParams`) |
| 가게 정보(영업시간 등), 클래스 마감 여부 | 빌드 HTML + 브라우저에서 최신 값으로 덮어쓰기 |
| 문의 폼, 관리 화면 | 브라우저에서 API 호출 |

공개 내용이 바뀌면 자동으로 재빌드한다:
1. 관리 화면에서 공개·수정·삭제 → FastAPI가 GitHub `repository_dispatch` 이벤트(`content-changed`)를 보낸다.
2. GitHub Actions가 prod API에서 내용을 받아 빌드하고 S3에 올린 뒤 CloudFront 캐시를 무효화한다.
3. 연속 수정은 `concurrency` 그룹으로 묶어 마지막 한 번만 빌드한다.
4. 관리 화면에 "사이트 반영 중 (약 3~5분)"을 표시한다.

## 보안
- GitHub 토큰은 이 저장소의 `contents: read`, `actions: write`만 가진 fine-grained 토큰을 쓴다.
- 토큰은 SSM Parameter Store(SecureString)에 두고, EC2 IAM 역할로 읽는다.

## 대안
| 대안 | 제외 이유 |
|---|---|
| 브라우저에서 API로 조회 (ADR 0004) | 검색 노출이 약함 |
| 서버에서 페이지 그리기 (SSR) | EC2 메모리 부담, CloudFront 앞 캐시 설계가 복잡해짐 |
| Next.js ISR | 정적 export(S3 배포)에서는 쓸 수 없음 |

## 결과
- 사장님이 공개를 누르고 사이트에 반영되기까지 몇 분 걸린다. 사장님께 미리 안내한다.
- 재빌드 실패는 GitHub Actions 알림과 텔레그램으로 운영자에게 알린다.
