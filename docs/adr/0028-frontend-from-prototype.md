# 0028. 프론트엔드는 사장님 쪽 프로토타입 디자인을 Next.js 정적 빌드로 옮긴다

- 상태: 채택
- 날짜: 2026-11-27
- 관련: ADR 0015 (빌드 시 HTML 생성), ADR 0027 (블로그 진열장)
- 대체: 2026-11-26 홈 시안 v1(한지 크림·나무 갈색, 저장소 밖 `design-drafts/`)

## 배경
사장님 쪽에서 디자인 전달서와 기능명세서를 보고 프론트엔드 프로토타입을 만들어 줬다
(`github.com/cd1070k987654321-beep/dohwa-frontend`, HTML·CSS·JS 약 90KB, 빌드 도구 없음).
- 손님 화면(C-01~C-17)과 관리 화면(A-01~A-11)을 모두 화면으로 만들었다
- 짙은 초록 + 밝은 종이색, 제목은 Cafe24 써라운드 에어, 스크롤에 따라 나타나는 움직임
- 접근성(본문 바로가기, 움직임 줄이기 설정 존중), HTML 이스케이프, 허니팟까지 갖췄다
- 데이터는 `data.js` 예시값, 저장은 브라우저(localStorage), 주소는 `#/plants` 같은 해시 라우팅이다

## 결정
| 결정 | 이유 |
|---|---|
| **프로토타입의 디자인(색, 글꼴, 레이아웃, 움직임)을 그대로 쓴다.** 시안 v1은 버린다 | 가게 주인이 직접 고른 디자인이다 |
| CSS는 클래스 이름 그대로 가져온다 (`frontend/app/dohwa.css`) | 디자인을 가장 정확하게 살리는 방법. 화면을 다시 그리지 않는다 |
| 문자열로 HTML을 만들던 함수(`header`, `section`, `plantCard`…)는 같은 마크업의 React 컴포넌트로 옮긴다 | 마크업이 같아야 CSS가 그대로 맞는다 |
| 해시 주소를 실제 주소로 바꾼다 (`#/plants` → `/plants/`) | 자바스크립트가 그리는 화면은 검색엔진이 잘 읽지 못한다 (ADR 0015) |
| Next.js App Router + `output: "export"` + `trailingSlash: true`, S3·CloudFront 정적 배포 | 서버 메모리를 쓰지 않는다. 기존 배포 구조(ADR 0021) 그대로 |
| 견적 문의는 프로토타입 경로 `#/quote` 대신 요구사항의 `/outreach/` | 문서와 QR·명함에 쓸 주소를 하나로 |
| 데이터는 API 응답 형태로 맞춘 예시값으로 시작하고, 페이지별로 빌드 시 API 조회로 바꾼다 | 화면을 먼저 확인하고 연동은 단계적으로 |
| 사진은 프로토타입의 예시 이미지를 당분간 쓰고 **출시(7단계) 전에 실제 사진으로 바꾼다** | 예시 이미지 일부는 실제 가게가 아닌 생성 이미지다. 교체 전에는 출시하지 않는다 |
| 글꼴: 프로토타입이 지정한 그대로. Pretendard는 프로토타입에 불러오는 코드가 없어 패키지로 직접 넣고, Noto Serif KR은 next/font로 | 지정만 되고 실제로는 PC 기본 글꼴로 보이고 있었다 |

## 프로토타입과 서버가 다른 부분 (연동할 때 서버 기준으로 맞춘다)
| 항목 | 프로토타입 | 서버(API) | 처리 |
|---|---|---|---|
| 견적 문의 필수 항목 | 기관 종류·유입 경로 없음, 인원 선택, 문의 내용 필수 | 기관 종류·유입 경로·인원 필수, 요청사항 선택 | 폼에 항목을 더한다 (디자인 전달서 8번) |
| 희망 일정 | 날짜 선택 | 자유 입력 | 자유 입력 (예: "12월 둘째 주 평일 오전") |
| 식물 크기 | 자유 입력 ("약 55cm") | 계획: 소·중·대 | **자유 입력으로 바꾼다** (블로그 식물 기능은 아직 안 만들었다) |
| 상태 값 | 한글 문자열 ("판매 중") | 영문 코드 (`available`) | 화면에서 한글로 바꿔 보여 준다 |
| 관리자 로그인·저장 | 데모 계정, localStorage | 서명 쿠키, API (ADR 0025) | API로 교체 |

## 결과
- 디자인 결정은 끝났다. 남은 일은 옮기기와 연동이다.
- 프로토타입 저장소는 디자인 원본으로 남겨 두고, 이 저장소에서 옮긴 코드를 관리한다.
