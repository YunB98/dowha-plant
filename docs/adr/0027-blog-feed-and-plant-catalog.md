# 0027. 블로그 글을 RSS로 가져와 식물 진열장으로 정리한다

- 상태: 채택
- 날짜: 2026-11-26
- 관련: ADR 0012 (주문은 받지 않는다, 유지), ADR 0013 (QR·가이드), ADR 0015 (빌드 시 HTML + 자동 재빌드)
- 일부 대체: ADR 0012의 "작품 갤러리" 행 → 식물 목록(`/plants`)

## 배경
- 도화의 본업은 **식물 판매**다. 출강은 늘리고 싶은 부업이다.
- 사장님은 네이버 블로그에 **주 1~2회** 글을 쓴다 (2026-01~11 50개). 매번 다른 식물을 예쁜 화분에 담아 소개하고,
  관리법과 공통 안내(맞춤 추천, 메시지 카드·리본, 배송, 연락처)를 붙인다.
- 글 종류는 제목 말머리로 나뉜다: `[전주 식물가게]` 식물 소개, `[전주 원데이클래스]`, `[전주 원예 출강]` 후기, `[전주 답례품 선물]` 단체 선물.
- 상품 사진은 이미 **같은 자리(한지 벽, 짙은 나무 틀, 나무 테이블)** 에서 같은 구도로 찍고 있다.
- 사이트에 같은 글을 또 쓰게 하면 사장님 일이 두 배가 되고, 결국 사이트가 방치된다.

## 측정 (2026-11-26, `https://rss.blog.naver.com/dowha_plantshop.xml`)
| 항목 | 결과 |
|---|---|
| 글 수 | 최근 50개 |
| 제목, 날짜, 태그, 원문 주소 | 있음. 태그가 풍부하다 (`개업화분`, `집들이선물`, `거실화분`, `공기정화식물`, 식물 이름) |
| 본문 | **앞부분 약 340자만** |
| 사진 | **365×365 썸네일 1장** |
| 썸네일을 우리 사이트에서 바로 표시 | **403** (Referer 차단). 서버가 받는 것은 200 |

## 결정
**블로그는 "이야기"(전체 글), 사이트는 "정리된 진열장"** 으로 역할을 나눈다.

| 결정 | 이유 |
|---|---|
| 서버가 한 시간마다 RSS를 읽어 새 글을 `blog_posts`에 저장 (systemd 타이머, 개인정보 삭제와 같은 방식) | 사장님은 지금처럼 블로그만 쓰면 사이트가 저절로 새로워진다 |
| 썸네일은 서버가 받아 S3 `images/blog/`에 사본을 둔다 | 네이버가 외부 사이트 표시를 막는다. 사본이라 CloudFront 캐시도 쓸 수 있다 |
| 사이트에는 제목·요약·썸네일·태그만, **전체 글은 블로그로 연결** | 같은 글이 두 곳에 있으면 네이버가 유사 문서로 보고 **블로그 검색 순위가 떨어질 수 있다**. 블로그가 지금 손님을 데려오는 통로다. 블로그 방문도 늘어난다 |
| 블로그 본문 페이지를 긁어 오지 않는다 | 네이버 화면 구조가 바뀌면 고장 나고, 관리할 코드가 늘어난다 |
| 말머리로 자동 분류: 식물 소개 → 식물 목록, 출강 후기 → 진행 사례, 클래스 → 클래스 페이지 | 사장님이 분류할 필요가 없다. 틀리면 관리 화면에서 바꾼다 |
| 블로그 태그를 정리된 필터로 바꾼다 (예: `전주개업화분`·`개업화분`·`전주승진화분` → **개업·승진 선물**) | 블로그 태그는 검색용이라 중복이 많다. 사이트는 고르기 쉬운 5~6개로 |
| 판매 정보(가격, 판매 상태, 크기)는 **원할 때만** 관리 화면에서 붙인다 | 매번 다른 식물이라 대부분 한 점이다. 판매 완료 글도 남겨 "비슷한 식물 추천받기"로 문의를 받는다 |
| 주문은 여전히 받지 않는다 (ADR 0012 유지). 버튼은 카카오톡·네이버 톡톡·전화 | 상담 후 판매하는 지금 방식 그대로 |
| 배송비는 고정값이 아니라 "크기에 따라 달라요" 문구로 설정에 둔다 | 크기별로 달라 숫자로 고정할 수 없다. 전주 8만 원 이상 무료는 공통 |
| 새 글이 들어오면 사이트 재빌드를 요청 (ADR 0015 `site_rebuild`) | 목록은 빌드할 때 HTML로 만들어 검색엔진이 읽는다 |

### 사이트만의 장점 (블로그가 못 하는 것)
1. 홈의 "이번 주 들어온 식물"이 블로그 글로 **자동 갱신**
2. 50개가 넘는 글을 **목적별(개업 선물·집들이·거실·초보자용·꽃 피는 식물)로 골라 보기**
3. **판매 중인 식물**을 위로, 가격·크기 표시
4. 같은 식물 이름의 **관리 가이드와 QR 카드**로 연결

## 구현 (2026-11-27)
- `blog_posts` (마이그레이션 0004): `guid`(원문 주소, 고유), `title`, `display_name`(사장님이 정한 짧은 이름), `excerpt`,
  `kind`(plant/class/outreach/gift/other), `tags`(원본), `purposes`(정리된 필터), `thumbnail_s3_key`, `published_at`, `is_hidden`,
  판매 정보 `sale_status`(available/reserved/sold), `price`, `size`(**자유 입력**, ADR 0028), `plant_guide_id`
- `backend/app/blog_import.py`: 매시간 systemd 타이머. 이미 있는 글은 건드리지 않는다 (사장님이 고친 값 보존)
- 손님 API `GET /api/v1/plants`, `/plants/{id}`, 관리 API `GET·PATCH /api/v1/admin/blog-posts` (A-05)
- 설정 `contact.naver_talk_url` 추가. 배송 안내는 설정 키 대신 상세 페이지 공통 안내 문구로 두었다
- 감시: `dowha_blog_import_age_seconds` > 6시간이면 `BlogImportStale` 경보

### 실제 글 50개로 고친 규칙
처음 규칙을 실제 RSS(2026-01~11, 50개)에 돌려 보고 바꿨다. 테스트에 실제 제목을 그대로 넣어 두었다.

| 문제 | 처음 | 바꾼 뒤 |
|---|---|---|
| 목적 태그를 블로그 태그에서 찾으면 검색용 태그(`전주개업화분`, `거실인테리어`)가 거의 모든 글에 붙어 있다 | 거실·매장 40개, 개업·승진 38개 (필터가 의미 없음) | **제목에서만** 찾는다: 21개, 23개 |
| "꽃이 피는 식물"을 "피어나"로 찾음 | 프랑스고무나무("열매 안쪽에서 피어나") 오판 | 제목의 꽃·카네이션·작약, 요약의 "꽃을 피우" 등. "꽃집" 제외 |
| 말머리가 없거나 다른 글 (`[전주 개업화분]`, 말머리 없음) | 13개 분류 안 됨 | 말머리 → 제목 전체 순으로 출강·클래스·답례품 단서를 찾고, 없으면 **식물** |
| 블로그 제목이 길어(최대 70자) 상세 제목이 6줄 | | 따옴표 안 이름(`'홍콩야자'`)을 먼저, 없으면 `|` 앞, 끝의 괄호 제거 (평균 27자) |
| 요약이 모두 같은 인사로 시작 ("안녕하세요. … 도화입니다.") | | 첫 인사 문장을 뗀다 (40개 모두) |

## 대안
| 대안 | 제외 이유 |
|---|---|
| 사이트에 같은 글을 따로 쓰기 | 사장님 일이 두 배. 유사 문서로 블로그 순위 하락 위험 |
| 블로그 본문 긁어 오기 | 깨지기 쉽고, 유사 문서 문제는 그대로 |
| 블로그를 iframe으로 넣기 | 네이버가 막고, 모바일에서 불편하고, 검색엔진이 읽지 못한다 |
| 블로그를 접고 사이트로 옮기기 | 이미 쌓인 네이버 검색 유입을 버리게 된다 |

## 한계
- 썸네일이 365px라 PC 큰 화면에서는 작다. 판매용으로 등록할 때만 원본 사진을 올린다.
- 네이버가 RSS를 바꾸거나 막으면 새 글이 안 들어온다. 가져오기 실패가 이어지면 경보(지표)로 알린다.
- RSS에는 최근 50개만 있다. 처음 한 번은 50개를 모두 가져온다.
