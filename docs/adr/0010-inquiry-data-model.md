# 0010. 문의 데이터 구조: 공통 테이블 + 종류별 테이블, 금액 스냅샷

- 상태: 대체됨 (ADR 0012)
- 날짜: 2026-11-19

## 배경
문의는 주문, 클래스, 단체·출강 3종류이고 입력 항목이 서로 다르다. 관리 화면에서는 한 목록으로 봐야 한다.

## 검토한 대안
| 대안 | 문제 |
|---|---|
| 테이블 하나에 모든 컬럼 (NULL 허용) | 종류별 필수값을 DB에서 강제할 수 없음 |
| 테이블 하나 + 종류별 정보는 JSONB | 상품·클래스와 FK 관계를 걸 수 없음 |
| 종류별로 완전히 다른 테이블 3개 | 관리 화면 목록을 만들 때 UNION이 필요함 |

## 결정
- 공통 정보는 `inquiries`, 종류별 정보는 `order_inquiries`, `workshop_inquiries`, `group_inquiries`에 1:1로 저장한다.
- 상품명, 가격, 클래스 가격은 **접수 시점 값을 복사**해서 저장한다.
- 상태값은 PostgreSQL ENUM 대신 `VARCHAR` + `CHECK` 제약을 쓴다.

## 이유
- 공통 테이블 하나로 목록과 상태 관리를 할 수 있고, 종류별 필수값은 각 테이블에서 NOT NULL로 강제한다.
- 상품 가격이 바뀌거나 상품이 삭제돼도 고객이 문의한 당시의 내용이 보존된다.
- ENUM은 값을 추가·삭제할 때 마이그레이션이 번거롭다.

## 결과
- 개인정보(이름, 연락처, 주소, 리본 문구)는 보관 기간이 지나면 자동으로 지운다. 통계용 정보는 남긴다.
