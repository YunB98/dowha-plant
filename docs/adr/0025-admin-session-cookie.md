# 0025. 관리자 로그인은 서명 토큰 쿠키, 계정은 서버 명령으로만 만든다

- 상태: 채택
- 날짜: 2026-11-26

## 배경
관리 화면 사용자는 사장님 한 명(필요하면 운영자 한 명)이다. 관리 화면은 손님 사이트와 같은 도메인(`dowha-plant.shop`)에서
CloudFront `/api/*` → Nginx → FastAPI로 들어온다. API 컨테이너 메모리는 160MB(ADR 0022), Redis 같은 세션 저장소는 없다.

## 결정
| 결정 | 이유 |
|---|---|
| 세션은 서명 토큰(itsdangerous)을 `HttpOnly·Secure·SameSite=Strict` 쿠키로, 14일 | 세션 저장소가 필요 없다. JavaScript가 토큰을 읽을 수 없어 XSS로 훔치기 어렵다 |
| 토큰에는 사용자 id와 `token_version`만. 요청마다 DB에서 사용자를 확인 | 비밀번호를 바꾸거나 `logout-all`로 버전을 올리면 이전 토큰이 바로 무효. 사용자가 적어 조회 비용이 작다 |
| JWT 대신 itsdangerous | 같은 서버가 발급·검증만 한다. 알고리즘 선택(`alg`) 같은 설정 실수의 여지가 없다 |
| CSRF는 `SameSite=Strict` + 변경 요청의 `Origin` 검사 | 같은 도메인이라 CSRF 토큰을 따로 주고받지 않아도 된다. 두 겹으로 막는다 |
| 비밀번호는 argon2id, 메모리 19MiB·2회 (OWASP 최소 권장) | 기본값(64MiB)은 동시 로그인 2건이면 컨테이너 한도에 닿는다 |
| 해시 계산은 한 번에 하나씩(lock) + `MALLOC_MMAP_THRESHOLD_` 고정 | 아래 측정 참고 |
| 계정은 API가 아니라 서버 명령(`app.admin_cli`)으로만 | 가입·초기화 API가 없으면 공격면이 줄어든다. 서버 접속은 SSM(IAM 로그인)뿐이다 |
| 실패 응답은 이유를 알려 주지 않고, 없는 아이디도 해시 검증을 한 번 한다 | 아이디가 있는지 응답 내용과 시간으로 알 수 없게 |
| 시도 제한은 Nginx(IP당 1분 5회), 실패 많으면 텔레그램 경보 | 앱 메모리에 카운터를 두지 않는다. 여러 IP에서 오는 시도는 경보로 사람이 본다 |
| 403 대신 401 | CloudFront가 403을 404 페이지로 바꾼다 (ADR 0021) |

## 측정: 동시 로그인과 메모리 (로컬, api 컨테이너 한도 160MB)
| 설정 | 동시 로그인 | api 메모리 |
|---|---|---|
| 기본 | 없음 | 74MiB |
| glibc 기본값 | 4건 × 3회 | **134~152MiB** (OOM 직전) |
| lock만 추가 | 4건 × 3회 | 152MiB (줄지 않음) |
| lock + `MALLOC_MMAP_THRESHOLD_=131072` | 4건 × 5회 | **67~76MiB** |

argon2는 해시마다 19MiB를 할당한다. glibc는 큰 블록을 한 번 해제하면 mmap 기준을 올려서, 이후 19MiB가
스레드별 힙(arena)에 남고 OS에 돌아가지 않는다. FastAPI는 동기 함수를 여러 스레드에서 실행하므로 스레드 수만큼 쌓인다.
lock은 동시에 쓰는 양만 줄일 뿐 남는 것은 막지 못했고, 기준값을 고정해 항상 mmap으로 받게 하자 해제 즉시 돌아갔다.

## 한계
- 토큰을 하나만 골라 끊을 수 없다 (전부 끊기만 가능). 사용자가 한두 명이라 충분하다.
- 2단계 인증이 없다. 계정이 늘거나 운영자가 외부 사람이 되면 TOTP를 추가한다.
- 서명 키(`session-secret`)가 새면 토큰을 위조할 수 있다. SSM SecureString에만 두고, 바꾸면 모두 로그아웃된다.
