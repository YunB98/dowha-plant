# 0020. prod 네트워크와 저장소 구성

- 상태: 채택
- 날짜: 2026-11-23

## 네트워크 (`modules/network`)
| 결정 | 이유 |
|---|---|
| VPC `10.20.0.0/16`, **퍼블릭 서브넷만** 2개 (2a, 2c) | 서버 한 대 구성. 두 번째 가용 영역은 나중에 로드밸런서·DB를 붙일 때를 위해 미리 둔다 (비용 없음) |
| **NAT Gateway 없음** | 월 4만 원 이상. EC2는 퍼블릭 서브넷에서 직접 인터넷에 나가고, 들어오는 트래픽은 보안 그룹으로 CloudFront만 허용한다 (다음 단계) |
| 서브넷 공인 IP 자동 할당 끔 | 공인 IP는 필요한 인스턴스에만 명시적으로 붙인다 |
| 기본 보안 그룹 규칙 비우기 | 실수로 기본 보안 그룹을 쓰면 아무 통신도 되지 않게 한다 |
| S3 게이트웨이 엔드포인트 | EC2 ↔ S3(사진, 백업) 트래픽이 인터넷을 거치지 않는다. 무료 |

## 저장소 (`modules/storage`)
| 버킷 | 용도 | 버전 관리 | 수명 주기 |
|---|---|---|---|
| `site` | Next.js 정적 빌드, 소개서 PDF | 끔 (CI가 언제든 다시 만든다) | - |
| `media` | 사진 | 켬, 이전 버전 30일 | `uploads/tmp/` 1일 후 삭제 |
| `backup` | DB 덤프 | 켬, 이전 버전 7일 | 30일 후 삭제 |

- 모든 버킷: 비공개, 공개 차단, ACL 비활성화, 암호화, HTTPS 강제.
- 외부 공개는 CloudFront OAC로만 한다. **버킷 정책은 storage 모듈만 관리**하고, CloudFront 배포 ARN을 입력받아 읽기 허용을 추가한다 (정책을 두 곳에서 관리하면 서로 덮어쓴다).
- `media` 버킷 CORS: 사이트 도메인에서의 업로드만 허용 (presigned POST).

## 다음 단계
- `modules/compute`: EC2(t4g.small), IAM 역할(SSM, S3), 보안 그룹(CloudFront 프리픽스 리스트만 443 허용)
- `modules/cdn`: ACM 인증서(us-east-1), CloudFront(OAC), Route 53 레코드
